这一节覆盖 DeploymentRun 如何推进、消息如何带 ID、以及「部署」按钮实际做什么。

任意阶段失败 → failed（保留错误与日志指针）。用户中止 → aborted。同一项目同时只允许一条 queued/preparing/building/deploying 记录。

数据流要点

RabbitMQ

Topic：deploy.sparkops

消息体只含：{"run_id":"...","workspace_id":"..."}

消费者按 DB 当前状态推进下一步；处理失败写失败原因并 ACK，不 Nack 死循环。Jenkins 结果走已有 webhook 或有限轮询，再发布「阶段完成」消息继续 CD。

持久化

deployment_runs：项目、集群、git ref、镜像 tag、状态、阶段时间线、失败原因、build_id

deployment_run_events：阶段日志（供 SSE）

Build 表保持 CI 专用；DeploymentRun 引用 Build，不把 K8s 状态塞进 Build。
