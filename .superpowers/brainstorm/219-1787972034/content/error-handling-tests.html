失败处理与测试范围

确认后会把完整设计写入 docs/superpowers/specs，再请你审阅文档。

失败策略

按阶段处理，不静默吞错
门禁失败
未审核 / 缺密钥 / 无集群		HTTP 400，不创建 Run，前端展示原因。
并发冲突同一项目已有进行中 Run → 409，不入队。
preparing
Jenkins Job upsert 失败		Run → failed。幂等：同一 run_id 重入只继续未完成步骤。
building
扫描/测试/推镜像失败		同步 Build 失败态，不 Apply K8s。日志走现有 SSE。
deploying
Apply 或 Rollout 超时		Run → failed，记录 K8s 错误。本次不自动回滚旧镜像（回滚另做）。
中止building 时 abort Jenkins；deploying 时停止等待，不删已 Apply 资源。

超时与重试

  • Jenkins 构建超时：可配置，默认 30 分钟 → failed
  • Rollout 等待：可配置，默认 10 分钟 → failed
  • MQ 消费：业务失败 ACK；仅连接/反序列化瞬时错误才重试
  • 用户可对 failed Run「重新部署」：新建 Run，不原地改旧记录

测试（第一期必须有）

后端
  • 门禁：未审核 / 缺密钥 / 进行中冲突
  • 状态机合法迁移与非法迁移拒绝
  • 消费者幂等：重复消息不重复触发 Jenkins
  • Build 失败不进入 deploying
  • Apply + Rollout Ready / 超时 mock runtime
前端 / 契约
  • contracts：DeploymentRun 类型与状态枚举
  • 部署按钮：approved 才可点；进行中显示进度
  • 详情「部署次数 / 最近部署」绑定真实 API

第一期不做真实 Jenkins/Harbor/K8s 集成测试；delivery.driver / runtime.driver 继续 mock 覆盖编排。
