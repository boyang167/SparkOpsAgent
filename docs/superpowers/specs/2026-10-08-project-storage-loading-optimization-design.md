# 项目持久化存储加载优化设计

## 背景

项目详情的「持久化存储」页签当前会在客户端同时请求 PVC 与 StorageClass。页面必须等待两个 BFF 请求全部结束后才退出全屏加载态。开发模式下 Next.js 路由按需编译、React 严格模式重复执行 Effect，加上每个 BFF 请求独立创建上下文并检查工作空间授权，造成首次进入时可感知的延迟和重复请求。

实测后端 Kubernetes 查询约为 14–120ms，完整 BFF 请求约为 0.7–0.8 秒，因此主要优化目标是减少 BFF 往返、合并并发请求，并避免刷新期间清空已有内容。

## 目标

- 首次进入页签只发起一个业务请求。
- 同一项目的并发加载合并为一个 Promise，避免 React 开发模式重复请求。
- 返回页签时立即显示最近数据，并在后台静默刷新。
- PVC 是核心数据；StorageClass 加载失败时仍展示 PVC。
- 创建、删除、绑定或解绑 PVC 后及时刷新，不能长期展示旧数据。

## 非目标

- 不引入新的前端数据请求库。
- 不修改 Kubernetes PVC、StorageClass 的业务语义。
- 不为所有项目页签建立通用缓存框架。
- 不处理 Next.js 开发模式本身的首次路由编译成本。

## 方案

采用「后端聚合接口 + 前端轻量 stale-while-revalidate 缓存」。

### 聚合接口

新增项目运行时接口：

`GET /api/v1/projects/:projectId/runtime/storage-overview`

返回：

```json
{
  "items": [],
  "classes": [],
  "warnings": []
}
```

后端完成一次项目访问校验并打开一次运行时会话，然后并行查询：

- 当前项目命名空间中的 PVC 与工作负载挂载信息。
- 集群 StorageClass。

PVC 查询失败时整个请求失败。StorageClass 查询失败时返回空数组，并在 `warnings` 中加入可展示的说明。这样 PVC 管理不会因辅助选项不可用而阻塞。

前端增加对应 BFF 路由、BFF module、upstream client 和 web SDK 方法。原有 PVC 与 StorageClass 接口保留，兼容其他调用方。

### 客户端缓存与请求合并

为 `ProjectStorageTab` 增加局部数据层，以 `workspaceId + projectId` 为键保存：

- 最近一次成功的 `items`、`classes` 和 `warnings`。
- 数据写入时间。
- 当前正在执行的 Promise。

缓存有效期为 30 秒：

- 无缓存：显示现有加载态并请求聚合接口。
- 有缓存：立即渲染缓存内容，后台刷新；工具栏显示轻量「刷新中」状态。
- 已有同键请求：复用同一个 Promise，不再发送请求。
- 请求成功：原子更新缓存及组件状态。
- 请求失败：有缓存时保留旧内容并显示非阻塞错误；无缓存时显示错误态。

组件卸载后不更新其本地状态，但允许共享 Promise 完成并写入缓存，用户返回页签时可立即使用。

### 数据变更后的刷新

创建、删除、绑定、解绑成功后：

1. 立即使当前项目缓存失效。
2. 请求聚合接口获取权威状态。
3. 操作期间保留当前列表，不退回整页加载态。

手动「刷新」强制绕过 TTL，但仍参与并发请求合并。

## UI 状态

- 首次加载：保留当前 `K8sLoadingState`。
- 后台刷新：内容保持可见；刷新按钮进入忙碌态并显示「刷新中…」。
- StorageClass 部分失败：PVC 正常展示，在创建表单附近显示提示，StorageClass 允许留空。
- 完全失败且无缓存：显示可重试错误。
- 完全失败但有缓存：显示旧数据和「刷新失败，当前为缓存数据」提示。

## 测试

### 后端

- 聚合接口一次授权后返回 PVC 与 StorageClass。
- 两项查询并行执行。
- PVC 失败时接口失败。
- StorageClass 失败时返回 PVC、空 `classes` 和 warning。

### 前端

- 无缓存时显示初始加载态。
- 有缓存时立即渲染并后台刷新。
- React 严格模式或并发调用只发一个请求。
- TTL 内返回缓存，手动刷新绕过 TTL。
- StorageClass warning 不阻塞 PVC。
- 创建、删除、绑定、解绑成功后失效并刷新缓存。

## 验收标准

- 热状态返回页签时不出现空白加载页。
- 首次进入只产生一个 storage-overview BFF 请求。
- 重复挂载或并发刷新不会产生重复上游请求。
- 后端聚合接口在当前环境下保持百毫秒级 Kubernetes 查询时间。
- PVC 仍可在 StorageClass 查询失败时查看和管理。
