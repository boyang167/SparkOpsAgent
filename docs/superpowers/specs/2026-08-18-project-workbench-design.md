# 项目创建后工作台设计

## 目标

用户完成创建项目第 1 步并成功保存基础信息后，直接进入项目详情工作台。工作台参考 `http://localhost:8082/#/layout/devops/project` 的项目卡片与进度表达，但保留 SparkOps 已有的项目成员、Agents、Workflows 关联能力。

## 用户流程

1. 用户在创建项目向导第 1 步填写业务空间、项目英文名、显示名称和描述。
2. 点击“下一步”时校验字段并调用创建项目接口。
3. 创建成功后关闭创建弹窗并跳转至 `/projects/{projectId}`，不再继续弹窗中的第 2 步。
4. 详情页顶部显示项目工作台卡片，进度停留在“创建项目”已完成、“配置完成”进行中。
5. 用户点击“继续配置”进入该项目的配置视图，完成 Git、资源和模板设置；每一步调用更新项目接口。
6. 用户可随时切换到项目成员、Agents、Workflows 区域管理项目关联资源。

## 页面结构

### 项目工作台概览

- 项目图标、显示名称、英文名、业务空间、语言、项目状态。
- 创建进度条：创建项目、配置完成、提交审核、审核完成。
- 数据指标：部署次数、构建次数、最后部署；后端暂无数据时使用 `0`、`0`、`N/A`。
- 操作按钮：
  - “继续配置”：打开项目配置视图。
  - “查看详情”：滚动或切换到项目基础信息。

### 项目配置视图

- 使用创建向导现有第 2、3 步字段：Git、认证密钥、引用、Dockerfile、资源、端口、命令、模板。
- 默认载入已保存项目值。
- 保存时调用 `workspace.updateProject(workspaceId, projectId, payload)`。
- 完成 Git/资源及模板配置后，概览进度更新为“配置完成”。

### 关联资源

保留当前项目详情页的现有功能和接口：

- 项目成员：`ProjectMembersPanel`，管理项目级 ACL。
- Agents：项目范围内创建、展示、进入 Agent。
- Workflows：项目范围内创建、展示与设置工作流。

关联资源区不依赖项目是否完成配置；未完成配置项目显示“创建中”状态，但仍可使用既有权限允许的关联功能。

## 状态计算

- “创建项目”完成：项目已存在。
- “配置完成”完成：已填写 `git_url`、`git_ref_value`、`dockerfile_path`，且已选择 `template_id`。
- “提交审核”“审核完成”：以 `2026-08-20-project-review-roles-design.md` 为准（Workspace 默认角色 + 项目 `review_status`）。

## 错误处理

- 第 1 步创建失败：保留表单内容并显示接口错误，不跳转。
- 配置保存失败：保留填写内容，显示错误，不更新进度。
- 项目不存在或当前工作区无权限：维持现有 `notFound` / 权限处理。

## 验证

- 第 1 步创建成功后跳转至新项目详情页。
- 工作台进度与已保存的项目字段一致。
- “继续配置”更新同一项目，不新增第二个项目。
- 项目成员、Agents、Workflows 的现有创建、查询与操作仍可用。
