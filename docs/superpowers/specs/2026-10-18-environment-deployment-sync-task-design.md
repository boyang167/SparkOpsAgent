# 环境部署同步任务设计

## 背景

产品工作流目前可以把构建产物或交付版本部署到指定环境，但没有一个正式的工作流任务可以把源环境的当前部署状态同步到目标环境。产品环境页面已有的“更新到环境”由前端直接调用 K8s 代理，不创建 `DeploymentRun`，也不能稳定回写环境状态，因此不适合作为工作流能力复用。

本设计在“部署”分类增加独立的官方任务“环境部署同步”，通过后端统一执行、审计和回写。

## 目标

- 用户可以选择源环境、目标环境和需要同步的项目。
- 源、目标环境在任务编辑时可设置默认值，运行工作流时可覆盖。
- 每个项目可以独立选择同步镜像或部署 YAML。
- 默认仅同步镜像仓库和当前 Tag。
- 目标环境未关联项目时，强制同步镜像和全部受支持的运行中 YAML；部署成功后自动建立关联。
- 工作流启动前必须预览并确认镜像变化和 YAML 差异。
- 多项目同步互不阻断，最终结果准确汇总成功与失败项目。
- 所有同步通过部署运行执行，保留进度、日志、审计和环境状态。

## 非目标

- 不支持跨产品或跨工作空间同步。
- 不自动删除目标环境中源环境不存在的资源。
- 不复制 Kubernetes Secret 密文。
- 不替代构建、交付版本或普通部署任务。
- 不在任务执行到一半时增加人工确认节点。

## 任务定义

新增任务类型：

- 类型：`sparkops-environment-sync`
- 分类：`deploy`
- 标题：`环境部署同步`
- 描述：`将源环境中的项目部署同步到目标环境`
- 后端执行器：`EnvironmentSyncExecutor`

任务 spec：

```json
{
  "source_environment_id": "env-source",
  "target_environment_id": "env-target",
  "projects": [
    {
      "project_id": "project-id",
      "sync_image": true,
      "sync_yaml": false
    }
  ]
}
```

约束：

- 源、目标环境必须属于当前产品且不能相同。
- 至少选择一个属于源环境的项目。
- 默认 `sync_image=true`、`sync_yaml=false`。
- 目标环境未关联项目时，后端把两项规范化为 `true`，前端同时禁用关闭操作。

## 配置与运行交互

### 任务配置抽屉

配置抽屉分为三个区块：

1. 环境范围：选择默认源环境和目标环境，目标列表排除源环境。
2. 项目与同步内容：展示源环境项目并默认全选；每个项目提供“镜像仓库 + Tag”和“部署 YAML”开关。
3. 安全说明：说明首次同步规则、YAML 不执行删除、Secret 密文不复制。

目标环境未关联的项目显示“首次同步”状态，两项同步内容自动开启且不可关闭。

### 运行时覆盖

运行表单允许按任务名覆盖：

- 源环境
- 目标环境
- 项目集合
- 每个项目的 `sync_image` 与 `sync_yaml`

修改上述任一字段后，已有预览确认立即失效。

### 预览与确认

用户必须先点击“生成同步预览”。预览按项目显示：

- 目标环境是否已关联项目
- 源镜像与目标镜像
- 将新增或更新的 Kubernetes 资源
- 资源字段级差异
- 不会执行的删除项
- 被安全规则排除的字段或资源

用户确认后，后端固化同步快照并返回 `preview_id`。启动工作流时必须提交对应的 `preview_id`。工作流执行使用已确认快照，不重新读取并静默采用源环境的最新状态。

## API 与运行输入

新增预览接口：

`POST /api/v1/products/:productId/environment-sync-previews`

请求包含源环境、目标环境和项目同步选项。响应包含：

- `preview_id`
- 规范化后的同步选项
- 项目级镜像差异
- 项目级资源差异
- 警告与不可同步项
- 快照校验摘要

工作流启动输入增加以任务名为 key 的环境同步覆盖与预览引用。后端在创建运行时校验：

- `preview_id` 属于当前产品与当前用户可访问的工作空间。
- 快照中的任务名、环境和选项与最终运行输入一致。
- 快照尚未被其他运行绑定。

校验成功后将快照绑定到工作流运行。绑定后的快照保留至部署历史清理，不使用短时缓存。

## 快照与部署运行

新增环境同步快照及项目明细持久化。快照保存：

- 产品、源环境、目标环境
- 创建人与确认时间
- 工作流与任务标识
- 项目同步选项
- 源镜像引用
- 清洗后的源 YAML
- 目标差异摘要
- 内容校验摘要
- 绑定的工作流运行 ID

每个项目创建一个 `environment-sync` 类型的 `DeploymentRun`，记录：

- 源环境 ID
- 目标环境 ID
- 同步快照 ID
- 是否首次同步
- 镜像/YAML 同步选项
- 来源工作流运行与任务名

同一项目已有活动部署时，该项目返回冲突错误，但不阻断其他项目。

## YAML 与镜像合并规则

### 仅同步镜像

- 读取目标环境现有的受管工作负载。
- 按项目资源身份及容器名匹配源、目标容器。
- 只修改容器镜像仓库和 Tag，不修改副本数、环境变量、探针或其他 YAML 字段。
- 资源归属或容器匹配不唯一时失败，不进行猜测。

### 仅同步 YAML

- 同步源环境受支持资源的非镜像字段。
- 目标已有工作负载时保留目标镜像。
- 如果 YAML 引入目标环境不存在的新工作负载，则该工作负载没有可保留镜像，使用源镜像并在预览中明确标记。

### 同时同步

- 使用源环境 YAML 和源镜像更新目标。

### 首次同步

- 强制同时同步镜像和全部受支持的运行中 YAML。
- 全部部署成功后才建立项目与目标环境的关联。

### 资源清洗与安全

应用前统一：

- 把 namespace 改为目标环境 namespace。
- 移除 `status`、`resourceVersion`、`uid`、`generation`、`managedFields`、时间戳等集群生成字段。
- 移除不应跨环境复制的集群级元数据。
- 沿用当前同步清单的受支持资源类型与应用顺序。
- Secret 只允许引用 SparkOps 已管理的凭据，不读取或复制源集群 Secret 数据。
- 只新增或更新，不删除目标环境多余资源。

## 执行流程

1. Scheduler 识别 `sparkops-environment-sync` 并调用 `EnvironmentSyncExecutor`。
2. Executor 读取已绑定的确认快照并再次校验环境权限。
3. 为每个项目创建项目同步状态和 `DeploymentRun`。
4. 项目按现有部署并发约束执行；单项目内按安全顺序幂等应用资源。
5. 单项目失败时记录资源级错误并继续其他项目。
6. 首次同步项目成功后自动建立目标环境关联。
7. 部署完成事件回写 `environment_projects` 的当前镜像、部署运行和状态。
8. 全部项目结束后汇总任务结果：存在任一失败则任务失败，并保留所有成功结果与失败原因。

工作流运行详情按项目展示状态、镜像变化、资源结果、错误以及部署运行链接。

## 错误处理与重试

- 源环境读取失败、环境无权限、项目不属于产品、资源归属不明确：对应项目失败。
- 目标项目已有活动部署：对应项目失败并提示冲突运行。
- K8s 部分资源应用失败：记录已成功和失败资源；项目失败。
- 自动重试或用户重试复用同一确认快照，所有 apply 操作必须幂等。
- 首次同步只有全部必要资源成功后才建立环境关联，避免产生虚假的在线项目。
- 快照缺失、被篡改或与运行输入不一致：任务在创建运行前被拒绝。

Kubernetes apply 不具备跨资源事务能力，因此不承诺失败时自动回滚已经成功应用的资源。运行详情必须明确部分应用状态，重试继续收敛到确认快照。

## 前后端改动边界

前端：

- contracts 增加任务 catalog、spec、预览与运行输入类型。
- 工作流编辑器增加默认 job、配置抽屉和校验。
- 运行表单增加覆盖、预览、确认失效逻辑。
- 运行详情增加项目同步结果展示。

后端：

- domain model 增加任务类型、catalog 和快照模型。
- product workflow 增加 spec 校验、运行输入和 `EnvironmentSyncExecutor`。
- delivery 增加环境同步部署运行创建路径及来源字段。
- product/delivery 通过端口读取环境项目、源环境实时资源并在成功后关联项目。
- 部署完成订阅者支持首次同步的 upsert 回写。
- 数据库增加快照和部署来源字段迁移。

## 测试策略

前端测试：

- catalog 展示与默认 spec。
- 源/目标环境互斥。
- 项目选择及首次同步强制选项。
- 运行时覆盖。
- 任一配置变化使预览确认失效。
- 镜像、YAML 和首次同步差异展示。

后端单元测试：

- spec 与运行输入校验。
- preview 与运行输入绑定校验。
- 镜像/YAML 四种合并路径。
- Kubernetes 字段清洗和 Secret 规则。
- 不删除目标多余资源。
- 首次同步成功后关联、失败不关联。
- 多项目失败后继续执行并汇总失败。
- 活动部署冲突和幂等重试。

集成测试：

- 源环境到已有目标项目的镜像同步。
- YAML 同步但保留目标镜像。
- 新工作负载使用源镜像。
- 缺失项目完整同步并自动关联。
- 部分项目失败时其他项目完成。
- 部署完成事件正确回写环境状态。

## 验收标准

- “部署”分类中可选择“环境部署同步”任务。
- 用户能配置并在运行时覆盖源环境、目标环境、项目和同步内容。
- 默认只同步镜像仓库和 Tag。
- 未关联项目自动执行完整同步，成功后出现在目标环境。
- 未确认预览不能启动包含该任务的工作流。
- YAML 同步不会删除目标多余资源或复制 Secret 密文。
- 每个项目都有独立、可追踪的部署运行。
- 单项目失败不阻断其他项目，任务最终状态和详情准确。
